# Commercial Judgment Lab v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Execution method for this project:** each task below is one card on the Notion board "CJL Dev To-do". Codex implements a card on a branch named `task-NN-<slug>`, opens a PR against `main`, and moves the card to Review. Claude audits the PR against the spec and this plan. Sean closes the card.

**Goal:** Build a static web app that presents construction commercial scenarios, grades the user's answer against a prepared rubric, and tracks weak skills across devices.

**Architecture:** A Vite + React single-page app deployed to GitHub Pages with no server. Scenario numbers and correct values are produced by deterministic TypeScript code; one grading module calls OpenAI to judge rubric points, and code computes every score. Records are append-only JSON, held in IndexedDB and synced as individual files to the user's private GitHub repo.

**Tech Stack:** Vite, React 18+, TypeScript (strict), react-router (hash routing), Zod, idb, CSS Modules, Vitest, @testing-library/react, fake-indexeddb (tests), tsx (scripts), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-04-cjl-v1-design.md`

## Global Constraints

- AI produces no numbers. Scenario numbers come from the instantiator; correct values come from the finance engine.
- AI does not assign scores. It returns a verdict per rubric point with a verbatim quote; code computes the score.
- Only `src/grading/` may call an AI API. Only `src/records/sync/` may call the GitHub API.
- The OpenAI key and GitHub token live only in browser local storage and are sent only to `https://api.openai.com` and `https://api.github.com`. They never appear in records, logs, thrown error messages, or the repo.
- No external scripts, fonts, analytics or CDNs. No vendor SDKs; use `fetch`.
- Runtime dependencies are limited to: `react`, `react-dom`, `react-router`, `zod`, `idb`. Adding another needs a stated reason on the card.
- No real company, project or person names anywhere in the repo. All scenario data is fictional.
- UI and scenario text are English.
- All percentages in engine inputs and outputs are numbers on a 0–100 scale (20 means 20%).
- All money is AUD, whole dollars, formatted `en-AU` with no decimals.
- Git commands run only inside `C:\Codex\Commercial Judgment Lab`, never from `C:\Codex`.
- Every page footer shows: "CJL is a training tool. It is not legal, accounting or financial advice."

## Review Focus

1. **Non-English answers.** An answer in Chinese must sync without error and its quoted evidence must match. Tests: Task 5 (evidence match), Task 8 (UTF-8 file upload).
2. **Grader output that omits a rubric point or invents an id.** The attempt must still score; missing points count as not met. Test: Task 5.
3. **Numeric answers typed the way people type them** (`900k`, `$900,000`, blank). Blank is not met, not an error. Tests: Task 5 and Task 11.
4. **GitHub token expires or is revoked.** Sync reports the problem, keeps the upload queue, and local training continues. Test: Task 8.
5. **Double submit and reload during grading.** One click makes one record; an attempt interrupted before a verdict arrives is kept as `pending_grade`. Test: Task 11.

Each function takes one object of named arguments and returns a number.

| Function | Arguments | Result |
|---|---|---|
| `eac` | `costIncurred, estimateToComplete` | sum |
| `forecastGp` | `contractValue, approvedVariations, forecastCost` | revenue − cost |
| `forecastGpPct` | same | GP ÷ revenue × 100 |
| `percentComplete` | `costIncurred, estimateToComplete` | incurred ÷ EAC × 100 |
| `earnedRevenue` | `contractValue, approvedVariations, percentComplete` | revenue × pct ÷ 100 |

| `profitFade` | `originalGp, currentGp` | original − current |
| `retentionHeld` | `claimedToDate, retentionPct, contractSum, capPct` | min(claimed × retentionPct, contractSum × capPct) |
| `peakCashDeficit` | `opening, netFlows: number[]` | largest shortfall below zero of the running balance, as a positive number; 0 if never negative |
| `markupFromMargin` | `marginPct` | margin ÷ (100 − margin) × 100 |
| `interestCost` | `principal, annualRatePct, days` | principal × rate ÷ 100 × days ÷ 365 |

```ts
export type Verdict = 'met' | 'partial' | 'not_met' | 'triggered' | 'not_triggered';
export interface GraderPoint { id: string; verdict: Verdict; evidence: string; comment: string }
export interface GraderOutput { points: GraderPoint[]; summary: string }

export interface PointResult { id: string; state: PointState; earned: number; possible: number; evidence: string; comment: string }

export function scoreAttempt(instance: ScenarioInstance, numericAnswers: Record<string, number | null>,
  answerText: string, graderOutput: GraderOutput | null): ScoreResult;
```

Scoring rules (spec 5.5, with two refinements marked ★):

- `numeric`: met when `|answer − truth| ≤ |truth| × tolerancePct ÷ 100`; when truth is 0, met when `|answer| ≤ 0.5`. `null` answer is `not_met`. `possible = weight`.
- `must_mention`: `met` earns weight, `partial` earns half, `not_met` zero. `possible = weight`.
- `red_flag`: in the attempt score, `triggered` adds `weight` to penalties and `possible = 0`.
- Evidence: a `met`, `partial` or `triggered` verdict requires `evidence` that is non-empty and contained in `answerText` after both are trimmed, whitespace-collapsed and lower-cased. Otherwise state is `unverified`, earning and subtracting nothing.
- A rubric point absent from `graderOutput.points` is `unverified`. Unknown ids in the output are ignored. A verdict of the wrong family for the point type (for example `triggered` on a `must_mention`) is `unverified`.
- `score = round(max(0, earned − penalties) ÷ totalPossible × 100)`; 0 when `totalPossible` is 0.
- ★ `skillTotals`: `numeric` and `must_mention` add their `earned` and `possible` to their skill. A `red_flag` adds `possible = weight` and `earned = weight` unless `triggered`, so that a skill tested only by red flags still gets data.
- `graderOutput === null` is valid only when the instance has no `must_mention` or `red_flag` points; otherwise throw.

- [ ] **Step 1:** Write `numeric.test.ts`: `'900000'`, `'900,000'`, `'$900,000'`, `'900k'`, `'0.9m'`, `' 900K '` all give `900000`; `'-175,000'` gives `-175000`; `'20%'` gives `20`; `''`, `'abc'`, `'9 hundred'` give `null`.
- [ ] **Step 2:** Write `scoring.test.ts` using one fixture instance with points: numeric `n1` (weight 2, truth 1,000,000, tolerance 1%), must_mention `m1` (weight 3), must_mention `m2` (weight 1), red_flag `r1` (weight 2). Cases:

  - `n1` answered 1,009,000: met; 1,011,000: not met; `null`: not met
  - `m1` partial: earns 1.5
  - `r1` triggered with matching evidence: `(6 − 2) / 6` → 67
  - penalties exceeding earned: score 0, never negative
  - `m1` met with evidence not in the answer: state `unverified`, earns 0
  - evidence differing only by case and line breaks: accepted
  - answer and evidence in Chinese (`"先确认 payment terms 再决定"`): accepted
  - grader output missing `m2`: `m2` is `unverified`, no throw
  - grader output with unknown id `zz`: ignored
  - `triggered` returned for `m1`: `unverified`
  - `skillTotals` matches the ★ rule for `r1` both triggered and not triggered
  - `graderOutput` null with AI points present: throws

```ts
  listPaths(): Promise<string[]>;               // every blob path in the repo; [] for an empty repo

}
```

Endpoints: `GET /repos/{repo}/git/trees/HEAD?recursive=1` (HTTP 404 or 409 means an empty repo), `GET /repos/{repo}/contents/{path}` with `Accept: application/vnd.github.raw+json`, `PUT /repos/{repo}/contents/{path}` with base64 content and message `cjl: add <path>`. Base64 must encode UTF-8 bytes (use `TextEncoder`), since `btoa` alone fails on Chinese text. HTTP 422 on PUT means the path exists.

`syncNow` order: push every queued item, dequeuing each on success; list paths; for each path under `attempts/` or `disputes/` not in `knownPaths`, download, validate, store, and mark known. A file failing validation is counted in `invalid` and marked known. On a `SyncError` the function stops, leaves remaining queue items in place, and returns the kind in `error` with `pending` set to the queue length. It never throws.

```ts
  history: { createdAt: string; ratio: number }[] }
```

Profile: only `graded` attempts count. For each skill take the attempts whose `skillTotals` include it with `possible > 0`, ordered by `createdAt`. The newest has weight 1; an attempt with `k` later attempts on that skill has weight `0.5^(k/10)`. `score = round(Σ w·earned ÷ Σ w·possible × 100)`. With fewer than 5 such attempts `score` is `null`. `history` lists `earned ÷ possible` per attempt, oldest first.

Selector: candidates are templates matching the level filter, minus the 5 most recently attempted distinct template ids; if that leaves none, the exclusion is dropped. `weakness(skill) = 1 − score/100`, or `1` when score is `null`. `weight(template) = (1 + mean weakness over its rubric skills) × (2 if never attempted, else 1)`. Pick by cumulative weight using `rng()`. No candidates returns `null`.
